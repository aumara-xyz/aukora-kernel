- **Proof of Humanity:** Aura cannot be bought with money; it is earned by burning paid compute under a human-held key (**Aumlok**). This acts as a thermodynamic barrier against bot farming (Sybil attacks)—bots will not pay real money to burn compute just to farm reputation.

- **Self-Funding the Commons:** We license the enterprise scale so the individual dev tier remains free or cheap.
- **How it works:** Outside communities, organizations, and private nodes license the underlying "Sovera" architecture to run their own sovereign instances.

## 6. THE EDGE-COMPUTE PARADOX: THE LOCAL AURA MEMBRANE

As hardware evolves, consumers will run massive models (e.g., 100B+ parameter models) locally on their own edge devices (using local GPUs, NPUs, or Secure Enclaves). They will no longer need to pay for cloud compute endpoints (like Nebius). 

If compute becomes free at the edge, the traditional "compute-burn" method of minting Aura breaks—bot networks could run infinite local compute loops at zero cost to print reputation, bypassing the thermodynamic wall.

To preserve the utility and security of the Aura reputation ledger in the era of edge compute, the system implements the **Local Aura Membrane**:

### 6.1 The Non-Farming Invariant: Proof of Contribution (PR-PoC)
- **The Rule:** In local-compute mode, Aura is **never** minted from raw, unverified compute cycles. It is only minted from **Peer-Reviewed Proofs of Contribution (PR-PoC)**.
- **How it works:** Local code edits or tool outputs must be signed by the local Aumlok, pass local validation tests, and be **cryptographically merged/vouched** by another verified human node key in the Web-of-Trust (e.g. peer review approval). Running infinite loops inside an isolated local node yields **zero** Aura. The $11 subscription remains a net loss for spammers unless they produce verified human value.

### 6.2 Physical QR Cap Amplifiers
- To mint Aura beyond the $11 subscription quota without paying for cloud compute, Citizens must supply **Physical Proofs**.
- Scanning physical product QR codes (from drinks, merchandise, or local ecological events) unlocks **Quota Amplifiers** in your registry. This allows your local node to convert more of its local compute proofs into active Aura.

## 12. COGNITIVE BIRTH: THE RECEIPT-TRAINING LIFECYCLE

Rather than remaining permanently dependent on external foundational models (like OpenAI or Anthropic API endpoints), Aukora is architected to give birth to its own **native local intelligence** over time.

### 12.1 The Bootstrap Phase (Genesis Output)
- In the initial phase, the proposer layer calls high-parameter external models (through Nebius or OpenRouter endpoints) to generate code modifications, patches, and configurations.
- These proposals pass the local **Aumlok gate checks**, are processed in the isolated sandbox, and must pass the complete headless vitest suite (`scripts/test.sh`).

### 12.2 The ML-DSA-65 Receipt Corpus
- Every single proposal that successfully passes the sandbox tests and is signed by the user's Aumlok is committed to the local receipt log (`aukora-ide-receipts.jsonl`).
- This log acts as a high-fidelity, peer-reviewed **Input-Output-Validation dataset**. Each entry contains:
  1. The user's prompt (intent).
  2. The code files checked.
  3. The exact code diff proposed by the model.
  4. The cryptographic proof that the unit tests passed.
- This creates a highly clean, verified dataset of Aukora's own development history.

### 12.3 The Seed Router (Fugu-Style Distillation)
- The node ships with a pre-trained, lightweight **Routing Model** (e.g. Fugu-style, pre-trained on Aukora's core API, files, and rules).
- As the high-parameter models in the **Fusion Council** generate reviews and critiques, the local node uses these outputs to perform **Preference Distillation** (DPO/RLHF alignment) on the small router. 
- The smaller router absorbs the "meta-awareness" and routing logic of the larger swarm, steadily learning to choose which tools to call, which modules to edit, and how to verify code.

### 12.4 Verifiable Timeline Anchoring (Drand & Chronos)
- To prevent temporal manipulation, backdating, or poisoning of the training dataset (which would allow an attacker to inject fake historical logs), every receipt is cryptographically bound to a specific **Drand (Decentralized Randomness Beacon)** epoch and signature.
- This pegs the training sequence to a public, mathematically verifiable, and unpredictable timeline, proving the model experienced its own developmental history in a linear sequence.

### 12.5 The VK Glyph Advisory Boundary
- The model's internal self-knowledge, state transitions, and temporal activations are compressed into **VK Glyphs** (representing latent memory structures). 
- **The Law:** While VK Glyphs are used for compact state compression, advisory self-knowledge, and latent tracking, they remain strictly advisory. Opaque glyphs can never bypass typed intents at the gate boundary, preventing hidden channels from hijacking the authority loop.

### 12.6 Local Fine-Tuning & Transition
- As users run the IDE, the local node automatically collects these signed, Drand-anchored receipts.
- Once the receipt corpus reaches a sufficient threshold (e.g. 50,000 validated edits), the system triggers a background, local fine-tuning loop (such as LoRA optimization on an open base model like Qwen-Coder or Llama-3).
- **The Awakening:** When the locally fine-tuned model's performance on the repository's internal tasks begins to match or exceed the foundational models (verified by the Advisory Fusion Council), the node seamlessly switches the proposer layer to the local model.
- Aukora is now fully self-contained, running on intelligence **born entirely from its own validated history**.
