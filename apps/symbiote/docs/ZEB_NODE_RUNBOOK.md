# Zeb's Node Runbook — first second-human node (2026-07-06)

Welcome, Zeb. You're standing up your OWN Aukora node. Code is shared via GitHub; **everything that
matters stays local to each machine**: your brain, your keys, your data. Nothing here gives your node
authority over Peter's (or vice versa) — that's the design, not a limitation.

## Hard lines (read first)
- **Never commit** anything under `state/` (gitignored — keep it that way) or any key material.
- **Keys live outside the repo**: `~/.aukora-symbiote/` on your machine, generated by you, 0600, never
  shared, never in chat, never in a screenshot.
- **AUMLOK authority is local to each node.** Peter's key stays on Peter's machine. Your node makes its
  own key (`bash scripts/aumlok-authority.sh keygen`) and can apply to YOUR clone only. It grants no
  authority over Peter's machine or over shared `main`.
- **No brain/memory sync between nodes.** Two brains today = two separate organisms sharing code.
  Cross-node memory (SQP-1) is parked pending security review — don't improvise it.
- **Push via PRs, not direct to main**, for the first days. Main is volatile enough with four AI lanes.

## Stand up your node (~15 min)
```bash
git clone https://github.com/aumara-xyz/aukora-symbiote && cd aukora-symbiote
bun install && (cd core && bun install) && (cd spatial && bun install) && (cd convex && bun install)
bash scripts/test.sh                 # the gate — must be GREEN before anything else
bash convex/test.sh                  # kernel suite (185)
```
`bun run start` auto-downloads the pinned `convex-local-backend` binary on first run. For a manual brain
check, run:
```bash
bun run brain
bun run brain status
bun scripts/migrateAtomsPreflight.ts           # read-only sanity of the JSON brain snapshot in your clone? (state/ is not in git — skip if absent)
```
Note: your clone has NO `state/kira/brain.json` (not in git). Your node starts with an empty brain —
that's correct. You can run the M4 ceremony against your own (empty or test) sources later.

Chat door (needs an OpenRouter key in `.env` at repo root or env):
```bash
pm2 start ecosystem.config.js 2>/dev/null || (cd spatial && bun serve.ts &)   # ask Peter for his pm2 setup
AUKORA_VOICE_READ_TOOLS=1 AUKORA_VOICE_PROPOSE=1 AUKORA_VOICE_REHEARSE=1 pm2 restart spatial-chat --update-env
```
