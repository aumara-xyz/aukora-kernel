## Body

## Why this exists
Auma's inside wishlist says: every workbench run she proposes should return evidence to her — diffs, tests, review verdicts, receipts — so she never says something landed without seeing proof.

## Goal
After an owner-approved `agent:`/`run:` or similar governed workbench action completes, the chat lane should receive a framed evidence packet summarizing what happened.

## Proposed packet
- Goal/proposal id.
- Commit/diff summary if any.
- Test command(s) and pass/fail summary.
- Receipt/provenance references.
- Fusion/adversarial review verdicts if present.
- Whether anything was applied live or only drafted/rehearsed.

## Boundaries
- Evidence is not authority.
- Chat cannot mark work complete by itself.
- Receipts/issues/git remain canonical truth.
- Raw secrets/logs are redacted or excluded.

## Candidate tests
- Successful run produces a framed evidence packet in chat context.
- Failed run produces a framed failure packet with no false success language.
- Draft-only/rehearsal-only runs are clearly marked as not live-applied.
- Secret-shaped values are refused/redacted.

## #51 landed — evidence packet returns to chat (commit `c1f389f`)

After a governed workbench action completes, the chat lane now receives a framed, **redacted, non-authority** evidence packet. Built as a pure module + wired into the `run:` and `draft intent:` handlers. **No live apply, no signing, no Fusion spend** — this is outbound framing only.

### `core/src/workbenchEvidencePacket.ts` (new, pure — no fs/network/clock)
`EvidencePacketV1` carries exactly the fields from the issue's proposed packet:
- goal, proposal id, intent id (#35 link)
- per-phase status: **proposal / test / fusion / receipt** (`ok | failed | not_reached`)
- terminal state (`DRAFT_ONLY | AWAITING_OWNER_SIGNATURE | FAILED_AT: <stage>`)
- **`appliedLive: false · advisoryOnly: true · grantsAuthority: false`** — literal-pinned. This rung never live-applies; a real live apply stays a separate owner-signed lane that will set `appliedLive` from a real receipt, never from chat.
- `redactions[]` — what was withheld and why.

### Boundaries held (straight from the issue)
- **Evidence is not authority.** The packet says so every time; chat cannot mark work complete.
- **Raw secrets/logs redacted.** Reuses the *canonical* redaction stack (one copy, never a second): `truncateHexRunsForCapture` (hex/keys/sigs collapse) → `scanForSecrets` / `scanForAuthorityLeakage` (burnDataset.ts). The scanned bytes are exactly the emitted bytes; a secret- or authority-shaped value is refused with a placeholder; reasons carry pattern *sources*, not secret values; only the summary — never the raw `redactions[]` — is rendered to chat.
- **No false "landed" language.** The summary is a controlled template, re-scanned by a **negation-aware** `findFalseLandedClaims` — honest denials ("nothing was applied to the live repo") pass; affirmations ("the change was applied to main", "is now live", "successfully deployed") are caught. Any slip is swapped for a safe fallback and recorded, never shown.
