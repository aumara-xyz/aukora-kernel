## Body

Captured from third-party static architecture/red-team review of the latest GitHub snapshot. Verify against current code before implementation.

Concern:
spatial/chat-serve.ts has an Origin check for POSTs, but the report flags dashboard/serve.ts /api/workbench/chat as potentially lacking the same local-CSRF guard. Localhost-only does not fully protect browser-driven blind POSTs from malicious pages.

Goal:
Every local POST endpoint should require a uniform local request guard.

Preferred policy:
- allowed Origin/Referer check for browser requests
- plus per-server CSRF/capability token injected only into served local pages
- curl/local tool path can be explicitly supported via token or absent-origin policy where safe

Acceptance:
- inventory all POST endpoints across spatial/, dashboard/, receiver/ or other local servers
- tests prove hostile Origin is rejected
- tests prove missing/wrong token rejected where token is required
- tests prove legitimate local UI request succeeds
- document endpoint policy in one place

Non-goal:
Do not add any new write authority. This is a guard around existing local POST surfaces.
