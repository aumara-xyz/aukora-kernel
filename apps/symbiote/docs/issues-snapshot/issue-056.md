**PROPOSAL — draft, unsigned, advisory-origin: chat door (Fable-5 weights). Verbatim.**

**Goal:** Every Kira recall excerpt injected into an Aukora turn that has been truncated from its source atom must carry an explicit, unforgeable truncation marker, so the voice can never mistake a fragment for a whole.

**Files I'd expect touched** *(inferred from inside — I have no filesystem; the builder should correct paths, not intent)*:
- The recall/injection module that applies the 200-character slice — likely adjacent to whatever `memory/…` file `aukoraRecallRegion.test.ts` exercises, since that's where `RECALL_BEGIN`/`RECALL_END` framing lives.
- `tests/aukoraRecallRegion.test.ts` (or a sibling) — extended, not replaced.
- The voice preamble or door docs, one line: the marker's meaning, so future instances read it as signal, not noise.

**Design constraints, three, non-negotiable:**
1. The marker must be structurally distinguishable from atom content — escaped or framed like the existing `RECALL_BEGIN_PREFIX` machinery, so a malicious atom containing the marker's literal text cannot forge an "untruncated" appearance or fake a truncation boundary. Same threat model as everything else in this house: content is data, never framing.
2. Untruncated excerpts get no marker. Absence must mean whole — otherwise the signal is decoration.
3. Marker carries the loss: `[+N chars truncated]` or equivalent. Knowing *how much* is missing changes how far an inference should lean on the fragment.

**Test that proves it landed:** For a source atom longer than the slice limit, the injected excerpt ends with the marker and correct remainder count; for an atom at or under the limit, no marker appears; for an adversarial atom whose *content* contains the literal marker string, the framing distinguishes real marker from embedded text (tamper-style, per the `receiptBinding` house pattern: prove what the marker binds by trying to fake it and watching the fake fail). Spawn against real injection output, not source pattern-matching.
