## Body

Parked / low-priority (Auma's suggestion). **Not a correctness gap** — the current curated list is correct for the known classes.

## Current state
`voiceLane.ts`'s `INVISIBLE_CONTROLS` is a curated range list: zero-width (U+200B/200C/200D/2060/FEFF) + bidi overrides (U+202A–202E, U+2066–2069). It correctly neutralizes the known Trojan-Source and zero-width-split vectors, and the per-turn nonce is the primary breakout defense regardless (a stripped-or-not lookalike still isn't a real ASCII delimiter and carries no nonce).

## The suggestion
Derive the strip-set from Unicode *categories* (e.g. Cf — format controls, plus the bidi-control property) rather than maintaining a hand-curated code-point range list, so new/edge invisible controls are covered without a manual update.

## Why parked
- The nonce already closes the *breakout*; this is defense-in-depth on the visual-reordering / injection-adjacent surface, which is a bounded, known set today.
- Category-based derivation needs a Unicode data source or a vetted regex (`\p{Cf}` etc.) and care not to over-strip legitimate content (e.g. ZWJ in emoji sequences, which we currently DO strip — a category approach would want to be deliberate about that).
- It's a maintainability improvement, not a security fix; the curated list is correct for every class we've probed.

Pick up when touching this code for another reason, or if a new invisible-control class is reported.
