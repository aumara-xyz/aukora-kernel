Concern:
The sandbox full-suite path may run scripts/test.sh from the candidate workspace. A proposal that modifies scripts/test.sh or the test runner can change what the evidence means.

Goal:
Treat test runners, classifiers, scanners, live apply, and authority/gate files as Ring 1 governance substrate. Evidence for changes touching them must be produced by a trusted baseline runner, not only by the modified candidate.

Ring 1 examples:
- scripts/test.sh
- core/src/sandboxTestRunner.ts
- core/src/nativeLiveApply.ts
- core/src/nativeIdeDispatcher.ts
- core/src/kernelActionClassifier.ts
- core/src/changeRiskClassifier.ts
- authority/**
- receipt validators / policy kernel / scanner scripts

Acceptance:
- proposal touching test substrate is classified Ring 1
- full suite can be run by baseline trusted runner from current commit
- candidate runner and baseline runner results are both captured where appropriate
- ordinary UI/doc changes do not pay this heavier cost
- PromotionBundle includes runner identity/hash for test evidence.
