## Body

## What surfaced this
The #53 envelope refactor renamed a request-handler variable `input` → `ownerText` across `spatial/chat-serve.ts`. One straggler (`kiraFallback(input)` in the inner-catch fallback) was missed. It's a runtime `ReferenceError` (swallowed by the inner catch, so the Kira memory fallback silently doesn't run when a command is unrecognized AND voiceReply throws). Adversarial review caught it; **tsc and the full 1917-test suite did NOT**.

## Root cause
`core/tsconfig.json` `include` is `["src/**/*", "tests/**/*"]` — it never typechecks `spatial/*.ts`. And the door (`chat-serve.ts`) is a `Bun.serve` module imported by no test (importing it would start a server), so vitest never loads it either. The result: `spatial/` runtime code has no static gate. A standalone `tsc --noEmit` on `chat-serve.ts` reports the error immediately; nothing in CI runs that.

## Fix options (pick when scoped)
1. A `spatial/tsconfig.json` (with `@types/bun`, `skipLibCheck`) added to `scripts/test.sh`'s typecheck step, so `spatial/*.ts` is gated alongside `core/`. This is the real fix. It may surface pre-existing type issues in `serve.ts`/`chat-serve.ts` (Bun globals) that need `@types/bun` — do it as its own scoped round, not bundled into a feature commit.
2. Interim: the source-assertion tests already pin the door's key wiring (lockdown placement, owner_text routing) — extend that pattern to assert no bare `input` identifier survives a rename, but that's brittle vs a real typecheck.

## Not urgent, but real
The envelope bug was caught and fixed (commit c4ae874). This issue is about closing the gap so the NEXT such bug is caught by the gate, not by review. Recommend #58 (voice read-tools) not land before this — read-tools add more door surface that a typecheck should cover.
