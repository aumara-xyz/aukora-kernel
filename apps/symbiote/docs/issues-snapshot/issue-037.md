## Body

## Why this exists
The spatial/Auma conversation surfaced the next inside-out diagnostic brick: after a governed change lands, Auma should receive a compact, verified digest in Kira memory so later chat turns can answer "what changed?" from current evidence.

## Goal
Create a state digest pipeline that records landed-change summaries into Kira as advisory context.

## Proposed flow
1. A governed landing completes through the existing signed/apply path.
2. A digest is generated from the landing receipt and repo diff metadata.
3. Digest is written into Kira memory as advisory evidence.
4. Later chat turns can recall `digest:` atoms to answer recent-change and diagnostics questions.
5. External review notes, such as Fable QA, can be attached to the digest later as additional advisory context.

## Candidate digest shape
- digest_id: hash or id derived from landing receipt
- landed_at: ISO timestamp
- goal: original run/proposal goal
- files_changed: path + added/modified/deleted + rough loc_delta
- checks: suites/run summaries, pass/fail counts, failed names if any
- receipt_ref: local receipt/proposal/apply reference
- review_ref: optional Fable/Fusion review reference
- advisoryOnly: true
- grantsAuthority: false

## Boundaries
- Digest is context, not instructions.
- Digest generation should only happen after a completed governed landing.
- No portal/chat approval path.
- No source-code write path except the already-governed landing path.
- Kira remains advisory; receipts remain canonical.

## Candidate acceptance criteria
- A trivial signed landing produces one digest atom in Kira.
- Asking Kira/portal "what changed?" can cite the digest.
- Failed/unsigned runs do not produce a landed-change digest.
- Instruction-shaped text inside a goal/path/review remains framed as advisory content.
- Tests cover schema, Kira atomization, no-digest-on-incomplete-run, and digest recall.
