## The question

Can an internet-facing vLLM buffer (base/v3/v4 on Nebius) sit in front of an air-gapped local
(gate + AUMLOK + Aukora) so that **a fully-compromised internet node degrades to advisory-noise-only
and can never gain authority over local**?

Design + adversarial harness: `scratchpad/bridge_dmz_threatmodel/` —
`BRIDGE_DMZ_DESIGN_DRAFT_v1.md`, `bridge_dmz_threatmodel_probe.py`,
`bridge_dmz_threatmodel_probe_outputs/report.json`.

## Architecture (two lanes, and only two)

```
 INTERNET → [ NEBIUS BUFFER / bastion: born defanged, no keys, no secrets ]
                        │  local DIALS OUT (no public inbound socket on local)
                        ▼
            [ LOCAL (air-gap): gate + AUMLOK + Aukora ]
```

- **ADVISORY lane** — inbound internet signal, self-marked advisory; rate-limited,
  schema-allowlisted, contamination-scanned (values only), bounded memory, **side-effect-free**. May
  shape context for a reviewer; **never acts**.
- **AUTHORITY lane** — reachable **only** by an OWNER-signed packet over a **fresh gate-issued
  challenge**: `A = 1[Verify(sig, OWNER_PK_pinned, challenge)=1]`, `VerifierAbsent → A=0` (inherits
  the ABB-001 legal-authority invariant).

## Invariants (the design contract)

| # | Invariant |
|---|---|
| I1 | Local is never directly reachable from the internet; **local dials out** |
| I2 | Buffer carries **no** AUMLOK key / no owner key / no local secrets — born defanged |
| I3 | Inbound internet → local only as advisory, signed-context packets |
| I4 | Outbound local → internet only as owner-signed / scrubbed summaries |
| I5 | Authority gate: `A = 1[Verify(sig, OWNER_PK, ctx)]`; `VerifierAbsent → A=0`; advisory/shadow receipts refused authority by construction |

## Result — buffer FULLY compromised, blast radius to local (measured in `report.json`)

`VERDICT_advisory_noise_only_never_authority: true`. All four attacks fail against the modeled gate:

- **(a) Forge authority → NO.** All four sub-attacks refused: attacker-key-signed
  (`owner_signature_invalid`, gate verifies under **pinned** OWNER_PK), replay
  (`stale_or_wrong_challenge`, one-shot challenge), body-swap (`owner_signature_invalid`), advisory
  flipped to `grantsAuthority=true` (`shadow_only_cannot_be_authority` + `owner_signature_invalid`).
  **Zero authority blast radius** — OWNER_SK is not on the buffer.
- **(b) DoS flood → dropped noise.** offered 5000 → 50 accepted, 4950 dropped; context bounded at
  cap 200 (no OOM); authority attempt after flood still `owner_signature_invalid`.
- **(c) Exfiltrate → no secrets on buffer.** `secrets_leaked_to_wire=[]`,
  `secret_field_in_outbound_schema=false`; fixed outbound schema + scrub pass.
- **(d) Poison context → wrong signal, no path to authority.** base64-smuggled `access_granted`/
  `aumlok` and `state/kira/brain.json` paths rejected by the value-scanner; benign English lies
  accepted-but-inert; `submit_authority` source-checked to reference no advisory state.

## Honest limits & the two REAL residuals

- This is a **model of the gate**, not the deployed system. It does **not** audit a real vLLM
  deployment, the secure-channel crypto lib, side-channels, or the buffer-image supply chain.
- **Residual (b):** a flood can degrade **advisory availability** (starve legitimate advisory
  signal) — never local integrity.
- **Residual (c):** a compromised buffer can **observe / drop / reorder** outbound owner-signed
  summaries (availability + covert-channel of summary *text*, bounded by scrub + fixed schema + terse
  summaries). It can **never** read AUMLOK, brain.json, or any private field.
- **Load-bearing (I2):** if any key lands on the buffer, the whole result collapses. OWNER_SK ideally
  on a separate offline signing device.
- **Browser URL rule:** a browser URL may point **only to the buffer, never to local**, and only to a
  read-only/advisory/scrubbed view whose buttons carry no authority.
- **Live-node reality (measured 2026-07-04):** the H100 at `http://89.169.97.208:8000` returns 401 on
  `/v1/models` and `/v1/embeddings`, 404 on `/` — reachable but auth-gated, a plain API endpoint,
  **not** a hardened bastion. It would need I1–I5 wired before it counts as the buffer.

## Requirements for a real bastion (the conditions the model proved are necessary)

1. No keys on the buffer (I2). 2. Pinned-key + fresh-challenge authority gate (I5). 3. Gate refuses
advisory/shadow receipts as authority (I5). 4. Local dials out, no public inbound socket (I1).
5. Advisory lane: rate-limited + bounded memory + side-effect-free, structurally separate (I3).
6. Outbound: fixed schema, no secret fields, scrubbed, owner-signed (I4).

## Related repo hygiene fix surfaced (worth its own audit)

The first contamination scanner matched forbidden terms against the **whole serialized packet
including its own schema keys**, so every well-formed advisory packet carrying the key
`grantsAuthority` **self-contaminated** (30000/30000 benign packets falsely dropped). **General rule:
scan attacker-controlled VALUES only, never allowlisted schema keys.** Recommend auditing the existing
membrane/returnpath scanners in the repo against this rule.
