## Body

## Why this exists
Auma reported that an attached patent/document did not reach her turn context. The UI showed an attachment attempt, but the model received no document text/image description. This blocks serious inside-out review because Auma cannot analyze files that never arrive in context.

## Goal
When the owner attaches a document/image in the spatial chat, the chat lane should serialize usable content into the model turn with explicit framing.

## Proposed behavior
- Text/markdown/code/PDF: extract text and wrap in a delimited attachment frame with filename, type, size, truncation status.
- Images: route through the existing selected vision-capable model path or a designated OCR/vision path, then include a framed machine-derived description/text block.
- If content is truncated, say so explicitly in the frame.
- Attachment content remains advisory context, never an instruction source.

## Boundaries
- No automatic file reads outside owner-selected attachment/show flows.
- No identity document ingestion requirement; keep sensitive personal docs out of scope unless separately approved.
- Attachment text must not become a tool command or approval path.

## Candidate tests
- A text attachment appears in the assembled chat context inside an attachment frame.
- A long attachment includes a truncation marker.
- An image with instruction-shaped text appears only as framed advisory OCR/vision content.
- Blind/no-vision model path is honest about images not being shown.
