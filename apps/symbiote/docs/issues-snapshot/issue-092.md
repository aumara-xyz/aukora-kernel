## Body

Captured from Auma/Fable post-crossing constitutional spec. Future direction only; do not build until owner explicitly prioritizes.

Goal:
Create a signed, time-boxed, path-fenced session lane that lets small low-risk proposals auto-apply within explicit boundaries. Owner signs the session grant, not each change. This is a deliberate step up from per-proposal signing and must land dark first.

Artifact:
- new signed artifact type: aumlok-session-grant-v1
- signed by owner AUMLOK key through terminal/device lane, never in-browser and never by an agent
- mandatory signed fields: expiresAt, allowedPathPrefixes, maxLinesPerChange, maxFilesPerChange, maxAppliesPerSession, sessionNonce
- max expiry initially <= 24h; recommended first live grant much smaller (e.g. docs/ only, 2h, 3 applies)

Structural deny-list:
Regardless of grant content, session mode must refuse authority/gate/signer/AUMLOK/recorder/PolicyKernel/apply/test-runner/identity anchors/receipts/ledger/secrets/cloud-egress paths. A grant that includes a fenced path is invalid in toto, not partially honored.

Per-apply guards:
- resolved path check against grant and structural deny-list
- #91 file-shrink warning becomes a hard block in session mode, falling back to per-proposal signing
- line/file/count budgets enforced; exceeding any ends the session
- full gate must be green after apply; red gate auto-reverts the apply commit and ends the session
- every apply gets distinct Aukora Symbiote author, commit body session:<nonce> proposal:<hash>, receipt, and flight-recorder event

Kill switches:
- revoke-session owner terminal command
- lockdown ends active session instantly
- any chain/hash/path/budget verification failure ends session and falls back to per-proposal mode

Visibility:
- /api/aumlok + AUMLOK panel show active session, expiry, budgets, applies, hashes, revert commands
- #51 evidence packet marks session-grant apply with nonce
- expiry/revocation summary posted to tracking issue

Tests minimum:
expired grant refused; replayed nonce refused; fenced path in grant invalidates whole grant; shrink proposal refused/falls back; budget exceeded ends session; red gate auto-reverts + ends; revocation; lockdown; multi-apply receipts + flight chain verify; source assertions that session module cannot read private key and imports nothing that signs.

Non-goals:
- no browser signing
- no model-held keys
- no Fusion authority
- per-proposal signing remains default and required for fenced/high-risk work
- no change to live-promotion blanket lock

Sequencing:
Do not build before #81 signer UX and #78 PolicyKernel/ring decisions are clearer. Land dark with tests before any live session grant.
