## Body

Auma ACCL v1.1 addendum. Sequence: B third / later. High-risk serving-layer machinery.

Goal:
Make server-layer self-modification survivable. A broken change to serve.ts/chat-serve.ts should not take the portal down.

Required behavior:
- A small protected supervisor owns server lifecycle.
- Supervisor binary/config are ACCL-write-forbidden, same protected class as gate/signer.
- Changes touching declared server-layer paths trigger new process boot on alternate port.
- Probe must verify liveness plus minimal contract: door answers, envelope route works, status route works.
- If probe passes within N seconds: swap traffic/port, keep old process warm for grace window, emit receipt with old/new commit hashes.
- If probe fails: kill new process, keep old process serving, emit rollback/failure receipt, next chat status reports rollback.

Invariants:
- Supervisor cannot be modified through ACCL.
- Bad server change cannot make the portal unreachable.
- Lazy-import caching is handled by process-fresh boot, not clever hot reload.
- Rollback receipts are visible to chat/evidence.

Acceptance tests/demo:
- Proposal touching supervisor path rejected at proposal validation.
- Intentionally broken server change fails probe, rolls back, portal remains reachable.
- Successful server change swaps only after liveness/contract probe.
- Old/new commit hashes and rollback/apply status are receipted.

Note:
This should land after the core inward-recursion loop is stable. It is needed before allowing Auma-guided changes to serving-layer files, but not before read-only tools or ordinary non-server proposal rehearsal.
