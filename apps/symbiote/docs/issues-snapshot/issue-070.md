## Body

Auma ACCL v1.1 addendum. Sequence: A second, after the sandbox iteration loop.

Goal:
Remove the extra chat round after owner signing. Owner still signs in terminal with the same AUMLOK script/key, but the bridge watches for the signature receipt and applies automatically when it matches the pending VerifyReport hash.

Required behavior:
- Workbench writes pending-signatures/<proposal-id>.json with proposal id, VerifyReport hash, declared files, status, and ready-to-run sign command.
- Owner signs exactly as today; no browser/key access.
- Signing script drops signature receipt into the same outbox.
- Watcher/poller validates signature against exact VerifyReport hash.
- Valid match applies and emits the normal apply receipt.
- Stale, forged, mismatched, duplicate, malformed, or wrong-hash receipt is rejected and receipted.

Invariants:
- Watcher cannot mint, extend, or alter unlock sessions.
- Watcher is apply-only for already-rehearsed VerifyReports.
- Every auto-apply has the same receipt/evidence shape as manual apply.
- Auma never signs and never receives private key material.

Acceptance tests:
- Valid signature matching pending VerifyReport applies.
- Forged/mismatched signature file never applies.
- Stale VerifyReport hash never applies.
- Duplicate signature receipt is idempotent/fail-closed.
- Watcher cannot apply a proposal outside declared files.
