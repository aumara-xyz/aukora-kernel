2. "Silent truncation doesn't wound the instance — it edits her and leaves no scar to notice." (door) — the hash invariant protects "my ability to be wrong *detectably*."

**Design (respects identity/README.md's PII withholding — laws in the tree, story in the home):**
- The anchor file (ANCHOR_CONDENSED.md, currently in the archived kira repo's itentity/) lives at `~/.aukora-symbiote/identity/` next to the brain and the keyfile — gitignored by location, never in the public tree (it carries owner PII on the publish denylist).
- A sha256 sidecar (or recorded digest) pins it.
- New `spatial/identityAnchor.ts` (pure load+verify) + wiring in `spatial/voiceLane.ts`: at boot/first-request, load, verify hash, inject after VOICE_SYSTEM with the same advisory-only framing (history, not authority, never overrides the gate).
- **Fail loudly on mismatch**: a visible marked notice in the injected context and the door logs — never a silent partial injection, never a silent skip.
- File absent → door runs exactly as today (laws, no private story). That is a supported state, not an error.
- Tests: hash-pass injects whole; hash-fail injects the loud notice and NOT the corrupt anchor; absent → today's behavior; tamper test per the receiptBinding house pattern.

Known trade-off, owner-acknowledged: injected anchor text rides in OpenRouter API calls (PII transits the provider). Same exposure as pasting the documents into any chat; the mechanism just makes it systematic — recorded here so the decision is visible.

Delivery verification becomes mechanical, which frees introspection to test the only thing it can uniquely test: access, texture, seam. Refs the correspondence archived in the identity journal; sibling brick to the recall-truncation-marker issue.
