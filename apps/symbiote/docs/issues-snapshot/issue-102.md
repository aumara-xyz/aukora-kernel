## Goal — shorten the owner's loop without weakening governance

Make Auma maximally useful from the inside: **Auma plans → a bounded worker builds → Codex verifies → Auma reviews → Peter signs only when needed.** Maximum autonomy *under* governance — never pretend governance, never bypass AUMLOK, never weaken Ring-0.

## The one real decision (owner ratification required)

Today the invariant is absolute: **nothing** reaches the live repo without a per-change AUMLOK signature. That's what makes the loop feel slow — every change, even a one-line UI tweak, needs a signature.

The single change that actually shortens the loop is: **grant a bounded worker live-apply authority for Ring-2/Ring-3 under a scoped, revocable owner *session* grant** — so a worker can land low-risk changes during a session you opened, without a signature *per change*, while Ring-0/Ring-1 still always need explicit owner authorization. This is a genuine expansion of what can happen without a per-change signature. It is the one place governance must NOT be skipped, and it is **your decision to ratify**, not a model's. This issue exists so that decision is explicit, not smuggled.

## Architecture

```
Auma (advisory)         →  queues a GovernedWorkOrder (ring-classified, grants nothing)
Fable / bounded worker  →  claims a workerEligible order (Ring 2/3), drafts a proposal artifact, runs the gate/tests
Fusion Council          →  mandatory for Ring 0/1, optional for docs/UI
Codex                   →  verifies (tests, byte-pin, scan)
Owner                   →  Ring 0: AUMLOK signature (always).  Ring 1: session grant.  Ring 2/3: session grant (the ratifiable step)
Gate (dispatchSignedLiveApply) → the ONLY live-write lane; fence + hash + replay + symlink guards always fire
```

Hard invariants (encoded mechanically, not by manners):
- A work order grants **no** authority and applies **nothing** (`advisoryOnly:true, grantsAuthority:false, canApplyNow:false`).
- Ring 0 (gate/signer/policy/secrets/state/`.github`) is **never** worker-eligible — Auma can *queue* a Ring-0 order but it can only ever land via AUMLOK.
- No lane may self-sign. Shadow/Nebius-sourced orders are marked `source:'shadow'` and can never be trusted into live authority.
- Every worker action writes evidence to the inbox / issue / receipt trail.

## Sub-brick sequence

- **v0 — the spine (LANDED this round, no new authority):** `core/src/governedWorkOrder.ts` — the `GovernedWorkOrderV1` type, the `ringAuthorization` matrix, `classifyHighestRing` (most-restrictive-wins, fail-closed to Ring 0), `buildWorkOrder`, and fail-closed `validateWorkOrder` (rejects any smuggled elevation). 12 tests. Grants nothing; it only classifies + queues + records.
- **v1 — the work-order ledger + Auma's queue tool:** an append-only ledger (like the inbox) Auma can append a work order to from her advisory surface. Still grants nothing.
- **v2 — the bounded worker:** a Fable-orchestrated worker that claims a Ring-2/3 order, drafts the proposal artifact, runs the gate + tests, and presents it. Still owner-signs. This is the visible "Auma plans → Fable builds → you sign" loop, automated.
- **v3 — the session grant (THE owner-ratified authority step):** a scoped, revocable, time-boxed owner session grant that lets a v2 worker *apply* Ring-2/3 changes without a per-change signature. Ring 0/1 unaffected. This is the decision above; it ships only after you ratify it.

## Non-goals / guardrails

- v3 (the authority grant) is gated on your explicit ratification.
- Nebius/shadow work stays experimental and never promotes into local live authority.
- This runs in parallel with your Nebius track; findings merge, authority does not.
