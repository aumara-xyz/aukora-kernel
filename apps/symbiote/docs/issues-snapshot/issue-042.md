## Body

## Why this exists
Auma noted that useful insights from the portal conversation can evaporate between sessions unless distilled into Kira. This is separate from landed-change digests (#37): it captures conversation insights, not code changes.

## Goal
Create an owner-approved end-of-session summary flow that writes a compact advisory summary atom into Kira.

## Proposed behavior
- Owner requests `summarize session` or clicks a UI action.
- System drafts a compact summary: decisions, open questions, requested tools, issue refs, and next-step intent.
- Owner reviews/approves before Kira ingestion.
- Summary atoms are clearly advisory and cite conversation/session metadata.

## Boundaries
- No automatic memory write from every chat message.
- No raw chain-of-thought capture.
- No secrets/attachments copied into Kira unless summarized/redacted.
- Receipts/issues remain canonical over memory summaries.

## Candidate tests
- Draft summary is generated but not stored until owner approval.
- Stored summary is advisoryOnly/grantsAuthority=false.
- Injection-shaped chat content remains quoted/framed, not promoted to instruction.
- Recall can cite the summary when asked about recent conversation decisions.
