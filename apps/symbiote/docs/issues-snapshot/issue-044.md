## Body

## Why this exists
Auma asked for richer file context but explicitly pushed back on ambient/self-directed filesystem access. The useful safe shape is owner-triggered read-only context injection.

## Goal
Add an owner-initiated command, such as `show: <path>`, that reads a repo-scoped file and injects its contents into the next chat turn using the same attachment frame as #38.

## Proposed behavior
- Owner types `show: <path>` or uses the UI to pick a file.
- Server reads only within allowed roots, rejects traversal/symlink escape.
- Content is framed as advisory attachment context.
- Auma may request a path in text, but that request never triggers a read unless the owner performs the command.

## Boundaries
- Read-only.
- Repo/local-library scoped, not whole computer.
- No identity documents or private home files.
- No reads triggered by model text alone.

## Candidate tests
- Valid repo file appears in a framed block.
- Missing file, traversal, symlink escape, and home/private paths are refused.
- A model-request-shaped line does not trigger any read without owner command.
