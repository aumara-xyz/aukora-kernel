## Body

Captured from third-party static architecture/red-team review of the latest GitHub snapshot. Verify against current code before implementation.

Concern:
AUMLOK-style signing of a proposal hash proves owner approval of the proposal, but may not cryptographically bind the full governance context: base commit, exact diff, sandbox receipt, tests, policy/risk classification, Fusion/Kira review, egress/capture state, and owner-visible challenge.

Goal:
Introduce PromotionBundleV1 and make live apply verify a signature over sha256(canonical(PromotionBundleV1)), not just a proposal hash.

Bundle should bind at minimum:
- proposal goal, files, beforeHash/afterHash/diffHash/contentHash, proposalHash
- repo baseCommitSha, tree/worktree clean proof
- ring/risk classification, policyKernelHash, reasons
- sandbox receipt hash, appliedLive=false, contentMatch=true
- typecheck/targeted/full test result hashes and durations
- Fusion/Kira advisory review hashes/verdicts if present, clearly advisoryOnly=true
- provider egress/capture metadata
- displayed summary/diff hash, nonce, issuedAt, expiresAt

Acceptance:
- stale base commit refuses
- changed diff after rehearsal refuses
- missing test/sandbox/policy fields refuse
- signed proposal hash without bundle refuses on live apply
- owner-visible challenge hash matches the signed bundle

Non-goal:
This does not make Fusion/Kira authoritative; it only binds their advisory evidence into what the owner signed.
