## Goal
A single workbench command, \`run: <goal>\`, that chains the existing pieces (native agent → fusion review → apply) into one legible, honestly-reported run — without overclaiming what each stage actually checked.

## Scope
1. Light refactor of \`core/src/workbenchCommandLoop.ts\`: extract the bodies of the existing \`agent:\`, \`run fusion review\`, and \`apply signed proposal\` branches into named helper functions, reused by both the old standalone commands and the new \`run:\` command (no behavior change to the existing commands).
2. Add a \`model\` field to \`NativeAgentRunResult\` (\`core/src/nativeToolCallingEngine.ts\`) — the engine already resolves the model via \`resolveAgentModel()\` but currently discards it before returning.
3. New pure module \`core/src/workbenchRunReport.ts\`: builds the human-legible report of a \`run:\` chain (stage-by-stage, honest labeling — see #4).
4. Honest stage labeling: the fusion review's content-match step must be reported as "content check", never "tests passed"; only a real \`tsc\`/\`vitest\` invocation may be labeled a typecheck/test pass.
5. Receipt persistence gap: the \`write receipt\` workbench branch is the one path \`captureWorkbenchEvent\` (from Round 3) was never wired into — fix that, and persist the run's receipt to \`${AUKORA_SYMBIOTE_HOME}/aumlok/receipts/<proposalHash>.json\`.
6. Failure-path honesty: if any stage in the chain fails, stop the chain, report a truthful partial result (which stages ran, which didn't, why), and do not write a receipt for a run that didn't complete.
7. Fix the stale comment at \`core/src/nativeToolCallingEngine.ts:13\` claiming \`runSandboxEngine()\` owns the tool-call sequence (flagged by Fable's QA, folded in here since it's adjacent to the \`model\` field change).
8. Disclose real-money cost (~$1/run, up to 8 agent calls) and the sandbox-inspection path directly in this issue before merging, so the cost is visible to whoever reads the issue trail — not just buried in a docstring.

## Acceptance criteria
- \`run: <goal>\` in the workbench chains agent → review → apply and produces a single report via \`workbenchRunReport.ts\`.
- No stage's report text claims more than what actually ran (adversarially checked).
- A receipt is written on full success at \`${AUKORA_SYMBIOTE_HOME}/aumlok/receipts/<proposalHash>.json\`, and is NOT written on any partial/failed run.
- Existing \`agent:\`, \`run fusion review\`, \`apply signed proposal\` commands behave identically to before (regression-tested).
- Full suite + typecheck green, fresh-clone verified, \`scripts/status.sh\` still \`HEADLESS_READY\`.

## Bug found and fixed while doing this
Wiring the missing \`captureWorkbenchEvent\` call into \`write_receipt\` (the one branch #23/Round 3 left uncaptured) surfaced a real, silent, pre-existing bug: every receipt embeds two 64-char sha256 hex fields (\`proposalHash\`, \`receiptHash\`). Passing the raw receipt JSON as Kira capture content trips \`kiraBrain.ts\`'s own secret-shaped-content guard (\`sanitizeText()\` throws on any 64+ hex-char run), and \`captureWorkbenchEvent\`'s advisory-only try/catch silently swallows it. That means the **existing** Round 3 \`workbench_live_apply\` capture had been failing on every single call since it was wired in — not something this round introduced. Fixed both call sites (write_receipt and live-apply) to pass a human-readable summary with truncated hash prefixes instead of raw JSON. The write_receipt fix is functionally regression-tested (real Kira capture confirmed on disk); the live-apply fix is structurally tested only, since that success path is deliberately unreachable from tests (dispatchSignedLiveApply has no override — always targets the real repo).
