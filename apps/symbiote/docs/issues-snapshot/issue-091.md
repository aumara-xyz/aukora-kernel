## Discovered live in the first owner-present #35 rehearsal (2026-07-03)

**What happened:** a `run: --from-proposal <id>` targeting the 362-line `docs/AUKORA_SYMBIOTE_SINGULARITY_PATH.md` produced a proposal whose artifact content was only **27 lines** — the agent (moonshotai/kimi-k2.7-code) reproduced just the first ~27 lines of the file. Since `propose_patch` is **full-file replacement**, signing + applying that proposal would have **deleted lines 28–362** (335 lines) of the doc.

**Every rail passed anyway — and that's the point:**
- sandbox apply: MATCH · content_check: MATCH · real typecheck: `tsc` exit 0 PASS (a `.md` change is tsc-invisible)
- Fusion review: **GREEN** — the council reviewed the *added sentence* semantically ("matches the stated goal exactly") and was **blind to the 335-line deletion**. (The latent-perceiver did fire a phase-lock/"RED insight" caution, but the verdict was GREEN.)
- The only thing that stopped it: **owner review before signature** (AUMLOK locked; nothing applied). Proposal proposalHash `209f35defe087a37…`, never signed, never applied — live doc untouched.

**Why this is a safety issue:** a truncating proposal is the highest-consequence, easiest-to-miss failure of a full-file-replacement apply lane. Today nothing in the evidence packet (#51) or run report signals "this proposal replaces a 362-line file with a 27-line one." A rushed owner could sign it.

## Ask
- The workbench (run report + #51 evidence packet) must **loudly flag** any proposal whose target file already exists and whose proposed content is substantially smaller (line/byte delta beyond a threshold, or a large net deletion) — a `⚠ FILE-SHRINK / possible truncation` warning that is impossible to miss in the evidence returned to chat.
- Consider requiring an extra explicit owner confirmation for a shrink beyond threshold, and/or having the artifact carry `beforeBytes`/`afterBytes` + `netLineDelta` so the sign-time review sees it.
- Fusion review prompt could also be given the before/after size delta so a large deletion isn't invisible to the council.

## Composes with
- #51 (evidence packet returns to chat) — the natural place to surface the warning.
- #73 (PromotionBundle binds base commit/diff), #82 (trusted test substrate), #35 (proposal authorship).

Non-goal: this does not change apply/AUMLOK authority — it makes a dangerous proposal *visible*, the owner still decides.
