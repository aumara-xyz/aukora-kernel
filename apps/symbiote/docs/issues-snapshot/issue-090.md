## Body

Direction captured from shadow-node architecture discussion. This is future/skunkworks planning, not a live build and not permission to upload memory.

Goal:
Create a defanged shadow node lane where an exported Kira/Aukora snapshot can eventually run in a contained remote rehearsal environment with no live authority, no local apply power, and cryptographic separation from the canonical local node.

Hard split:
- Phase 0a is local-only: export snapshot copy, scrub/allowlist, produce human-readable scrub report, encrypt locally, stop. No cloud upload. No remote compute.
- Phase 0b is egress: owner reviews scrub report, explicitly approves upload, and the export event is receipted on the live chain. A memory fork leaving the local node is not logistics; it is a ledger event.

Required invariants:
- Born defanged: no AUMLOK keys, no signing authority, no live promotion, no local apply lanes.
- Shadow receipts are cryptographically distinct and stamped shadow_only:true.
- nativeLiveApply must refuse any shadow_only receipt or shadow identity output.
- One-way flow first: local -> shadow only. No return patch/apply lane until explicitly designed and tested.
- Scrub before egress: snapshot pipeline must route through forbiddenContent scanners (scanForbiddenKeys/scanForbiddenValues or successor), strip local paths/secrets/shell-history-like data, and emit a scrub report.
- Encrypt before external storage: AES-256-GCM or existing project crypto standard before any bucket/cloud write.
- Owner holds kill/tunnel/TTL credentials. Agents may operate within the shadow but cannot own the shutdown or authority keys.
- Shadow voice must self-identify as shadow in any conversational surface.
- LoRA/weight artifacts trained on shadow traces inherit shadow confinement: shadow_only, propose-never-authorize, no auto-deploy.

Acceptance sketch for Phase 0a:
- snapshot export works only against a copied brain file, never live brain surgery in place
- scrub report lists counts/classes removed without exposing secrets
- encrypted artifact can be decrypted locally and verified against expected sanitized schema
- tests prove forbidden keys/values/local paths are removed
- no network or cloud write occurs in Phase 0a tests

Acceptance sketch for Phase 0b (future owner-gated):
- owner approval recorded before upload
- export event receipted on live ledger
- artifact stored encrypted only
- remote shadow identity and receipts cannot pass local live-apply validation

Sequencing:
This does not block or accelerate the main recursion ladder (#53 -> #58 -> #35 -> AUMLOK -> receipt -> #51). It is a skunkworks lane and should not be used to bypass owner authority.
