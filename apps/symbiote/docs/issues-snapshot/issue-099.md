## Problem

#97 fenced the live-apply gate MACHINERY against one-signature self-unlock. The same bug class still applies to
the organism's STATE/BRAIN, its SECRETS, and several ratified-Ring-0 authority paths the #97 fence did not cover.
The live-apply writer writes each file to disk **before** the git commit; a gitignored `.env` / `state/**` path
would be poisoned on disk even though the commit then fails (`git add` refuses ignored paths), and the running
organism reads its env/brain **from disk**, not from the commit. So the only safe stop is a **pre-write deny**,
exactly like the gate fence.

This also closes the #97 residual: the fence was name-string only, so a pre-existing intra-repo symlink could
route a write into a protected dir. This brick re-checks the **resolved real path**.

## What landed

A unified pre-write Ring-0 apply deny, `isRing0ApplyTarget = isGateMachineryTarget (#97) ∪ isProtectedStateEnvTarget`,
checked in `applyCore` step 0 (before any signature/hash/replay), restated in `validateAllFilesOrRefuse`, and
**re-checked against the resolved real path** so a symlink cannot route around the name-string.

New protected categories (never applyable by any signed proposal):

- **(A) Live brain/state data** — `state/**` (`state/kira/brain.json` + backups): the brain-poisoning target.
- **(B) Env & secret files by basename** — `.env`, `.envrc`, `.env.<x>` (except the non-secret shapes
  `example|sample|template|dist|defaults`), `*.key`, `*.pem`, `auth.json`, `aumlok-dev.json` (the `.gitignore`
  secret list). Planting one on disk redirects model-routing / egress / auth.
- **(C) Ratified-Ring-0 authority paths the #97 fence missed** (all Ring 0 in `docs/policy-rings/ring-table.json`):
  `core/src/pinnedPublicKey.ts` (the **pinned public key** — a rewrite is straight authority substitution),
  `core/src/nodeIdentity.ts`, `scripts/aumlok-authority.sh`, `scripts/scan-secrets.sh`, and
  `scripts/verify-public-readiness.sh` (the leak scanner's real logic — `scan-secrets.sh` only `exec`-wraps it).

Also:
- **Owner-facing surfacing** (mirrors #97 item 3): `kernelActionClassifier.ts` flags these targets as
  `sacred / never_ring0` so the workbench evidence warns before the owner signs. Advisory; the fence is authoritative.
- **CI**: new `.github/workflows/gate.yml` runs the headless gate (`scripts/test.sh`) + the gate byte-pin
  (`shasum -c`) + the TIER-1 secret scan on every push and PR — the fence is now verified on every push.
