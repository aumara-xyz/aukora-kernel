## Body

Captured from third-party static architecture/red-team review of the latest GitHub snapshot. Verify against current code before implementation.

Concern:
Repo read/search/self-map paths may use lexical checks plus statSync/readFileSync. statSync follows symlinks. A malicious symlink inside the repo could expose files outside the repo to read_file, search, or Kira self-map ingestion.

Goal:
One shared resolver for all repo reads and self-map ingestion.

Proposed API:
resolveRepoReadPath(relPath) -> { ok:true, abs, real, rel } | { ok:false, reason }

Rules:
- input must be repo-relative
- no .. traversal
- use lstatSync before following anything
- deny symlinks by default, or only allow symlinks whose real target remains inside repo
- check sensitive path policy on both lexical path and realpath
- apply to nativeIdeDispatcher read/search, Kira ingestSelfMap, code map/self-map, and any future #58 read-tools

Acceptance tests:
- repo/docs/leak.md -> /tmp/outside-secret.md refused by read_file
- repo/core/src/leak.ts -> /tmp/outside-secret.ts refused by search
- symlinked file refused by Kira self-map ingestion
- allowed normal files still read/search/ingest
- resolver used by #58 read-tools before they ship.
