## Body

## Why this exists
Before Auma gets read tools or proposal tools, every capability call must be measurable. This is the evidence base for earning later stages.

## Goal
Add an append-only JSONL flight recorder for every Auma capability call from the first read-only tool onward.

## Proposed event fields
- schema/version
- turn hash / conversation id
- capability name
- arguments digest and bounded/redacted args preview
- result status
- result digest / error reason
- timestamp
- branch/HEAD when relevant
- AUMLOK/capability-mode snapshot when relevant

## Boundaries
- Append-only local state, not authority.
- No secrets, raw private keys, env values, or huge file contents.
- Recorder failure should fail closed for promoted capabilities: if a capability cannot be logged, it should not run.

## Candidate tests
- Capability call writes one JSONL event.
- Redaction/size caps work.
- Recorder failure blocks the capability and returns an honest error.
- Later tests can count clean read sessions from this log.

## #54 follow-up landed — the flight recorder is now hash-chained (commit `6062973`)

The recorder built earlier hashed each event's own bytes but explicitly deferred a full prev-hash chain. That's now closed: `flightRecorder.ts` computes each `eventHash` over its own bytes **plus the previous event's `eventHash`** (genesis for the first of a day), so tamper / reorder / insert / delete all break the chain.

- **`verifyFlightChain(dir, now)`** → `{ok, length, brokenAt, reason}`, distinguishing content-tamper (eventHash mismatch) from broken linkage (prevHash mismatch) from a bad genesis.
- **Redaction hardened**: `safeText` now hex-collapses *and* runs the canonical `scanForSecrets` — a residual secret-shaped value (e.g. an `sk-or-*` key that isn't pure hex) is redacted to a marker before being written or hashed, so the chain stays intact.
