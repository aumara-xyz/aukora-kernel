**The bug:** `authority/gate/risk.ts`'s `isGlobalExecLoadDir(p)` computed `const rest = vn.slice(dn.length)` without first checking `vn.startsWith(dn)`. This answers the wrong question: it doesn't test "is `p` inside the sensitive global opencode config dir," it tests "does the substring starting at character-index `dn.length` match this narrow pattern" — completely independent of whether `vn` actually starts with `dn`.

**Empirical reproduction (before fixing anything):**
```
dn = [REDACTED:local-user-path] (length 36)
constructed path: xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx/tool/evil.ts  (36 arbitrary chars + /tool/evil.ts)
rest after slice: /tool/evil.ts
WOULD MATCH: true
does vn actually start with dn? false
```
Any path whose first `dn.length` characters are arbitrary, followed by `/tool/evil.ts` (or `/plugin/`, `/config.json`, etc.), is misclassified as being inside the sensitive global config directory — a false positive, not narrowed away by the pattern regex (which only constrains what comes *after* the wrongly-computed slice point).

**Fix:** added `if (!vn.startsWith(dn)) continue;` before the slice, in both copies of the file that exist in this repo (`authority/gate/risk.ts`, the active/tested one, and `self_edit/opencode/session/aukora/risk.ts`, a byte-identical vendored duplicate inside the quarantined fake-OpenCode-fork directory — kept in sync for consistency even though the surrounding fork is dead/non-compiling code).

**Also exported** `isGlobalExecLoadDir` (previously module-private) so it can be unit-tested directly — the full `aukoraGate()`/`classifyRisk()` integration path has an unrelated "deny outside workspace" check that fires first for most synthetic test paths, making this specific check impossible to isolate through the gate alone without also faking a real workspace directory.

**Tests added** in `core/tests/aukoraReadGate.test.ts`: (1) the exact length-coincidental construction above now correctly returns `false`; (2) a real path genuinely under the configured global dir still correctly returns `true` (no regression) for `tool/`, `plugin/`, and `opencode.json` paths, and correctly returns `false` for an unrelated real subpath.
