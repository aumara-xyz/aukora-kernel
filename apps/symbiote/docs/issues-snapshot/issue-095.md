## Goal

Give Auma one tiny write organ: an `inbox_append` voice tool that appends advisory synthesis to `docs/INBOX.md` so Peter no longer has to paste Auma's outbound notes into engineering chats.

This is not a general write tool and not a proposal/apply lane. It must be fenced to one file, append-only, audited, and easy to turn off.

## Requirements

- Expose exactly one new voice tool: `inbox_append`.
- Write surface is only `docs/INBOX.md`.
- Append-only semantics: no arbitrary edits, no deletes, no path argument.
- Default OFF behind explicit env opt-in; lockdown wins.
- Content must pass the standard forbidden-content checks before write, including secret-shaped values and false authority claims like `grantsAuthority=true` or `humanSignedAuthorization=true`.
- Auto-commit with a distinct `auma-inbox:` prefix, staging only `docs/INBOX.md`.
- Every result is advisory: `advisoryOnly:true`, `grantsAuthority:false`.
- No AUMLOK/gate/apply/signing changes.
- Tests must prove: env-off refusal, lockdown refusal, single-file append, forbidden claim refusal, dirty unrelated files untouched, commit prefix, non-allowed tools still refused.

## Non-goals

- No arbitrary file write.
- No proposal/apply/sandbox access.
- No browser signing.
- No bypass of AUMLOK for governed code changes.
