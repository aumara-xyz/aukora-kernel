## Body

## Why this exists
Auma can notice issues from inside the chat experience, such as silent truncation or missing attachment content, but today those observations only survive if the owner manually relays them.

## Goal
Add a governed `finding:` capture path where Auma/owner can record an inside observation as advisory evidence or a draft GitHub issue for owner review.

## Proposed behavior
- Chat can produce a structured finding draft: title, observed behavior, expected behavior, evidence text, related issue/file if known.
- Owner reviews before it becomes a Kira atom or GitHub issue/comment.
- Findings are advisory and do not trigger code changes directly.

## Boundaries
- No automatic GitHub issue creation from model text alone.
- No tool execution, signing, or source writes.
- Owner approval required for persistence beyond the transcript.

## Candidate tests
- Finding draft can be created from text.
- Draft does not persist until owner approval.
- Approved finding becomes advisory Kira atom or issue comment with clear provenance.
- Instruction-shaped content in finding body remains framed as evidence.
