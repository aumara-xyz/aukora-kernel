## Body

Captured from third-party static architecture/red-team review of the latest GitHub snapshot. Verify against current code before implementation.

Concern:
Provider/model calls are not just implementation details. They are cost, privacy, and evidence flows. fusionConfig may discover keys from local tool auth (for example OpenCode auth), which can surprise users.

Goal:
Make provider egress explicit, consented, and receipted.

Required behavior:
- On first use of a discovered provider key outside Aukora config/env, ask owner consent.
- Persist consent outside repo under ~/.aukora-symbiote.
- Receipts include providers contacted, model ids, raw capture persisted yes/no, capture paths, approximate cost if available.
- UI/CLI shows provider egress before spendful live runs.
- Deny if key source is discovered but not consented.

Acceptance:
- discovered OpenRouter key from external auth refuses until consent
- explicit Aukora env/config key works as before
- receipts capture provider/model/cost metadata
- no raw secrets appear in receipts/logs
- spendful runs remain owner-approved.
