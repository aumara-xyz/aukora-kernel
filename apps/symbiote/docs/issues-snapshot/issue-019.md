## Body

Direct continuation of the "build Symbiote's own IDE from the inside out" goal. Previously the Workbench chat (`workbenchCommandLoop.ts`) was a purely deterministic string-command parser — no model ever decided what to call next. This adds the first real, autonomous, tool-calling LLM agent native to this repo.

**Design, deliberately narrow:** exposes only 6 of the existing 10-tool `ideToolContract.ts` surface to a real model via OpenRouter function-calling: `status`, `self_map`, `list_files`, `read_file`, `search` (pure exploration, already bounded/advisory), and `propose_patch` (drafts + hashes only, writes nothing). `sandbox_apply`/`run_tests`/`write_receipt`/`rollback_sandbox` are NOT exposed to the model — those stay owned entirely by the already-built, already-tested `sandboxEngineBridge.ts`'s `runSandboxEngine()` gated pipeline (classify → permit → temp-only apply → receipt), which this module hands a candidate to but never calls itself. Every dispatched tool call routes through `dispatchIdeToolWithState` — the same single chokepoint every other caller in this repo uses.

The model explores the repo however it wants, then calls `propose_patch` exactly once to submit its answer — that call's `files` become the terminal candidate. This module is currently **inert/unwired** — nothing else in the repo calls `runNativeAgent` yet; wiring it into the live Workbench (and deciding whether to route its output through `runSandboxEngine()` automatically or require an explicit follow-up command) is left for a future round, deliberately, since the owner wants to build the actual chat-UI experience live rather than have it appear pre-wired.

**Adversarially reviewed (4 lenses) before commit:**
1. **no-new-authority-surface** — PASS. `EXPOSED_TOOLS` is a fixed 6-name array; every model tool-call name is checked against it BEFORE ever reaching the dispatcher; a hallucinated name (e.g. `sandbox_apply`, `eval`, `__proto__`) is refused pre-dispatch, never executed.
2. **fail-closed-behavior** — CONCERN found and fixed before commit: `callModel()`'s `fetch()`/`resp.json()` had no try/catch (only the explicit HTTP-status-error path was handled) — a real network throw or malformed-body response would have propagated as an unhandled exception instead of the documented clean `model_error` stop reason. Fixed; added 2 regression tests (`network_throw`, `malformed_json` cases).
3. **dispatcher-chokepoint-integrity** — PASS. Zero `fs`/`child_process`/`eval` in the file; the only network call is the model provider; `rawSandboxPath` (the internal side-channel documented in `nativeIdeDispatcher.ts`) never appears here at all since `sandbox_apply` isn't exposed.
4. **real-network-call-safety** — PASS. API key confined to one `Authorization` header use, never echoed into any return value or log; fixed OpenRouter endpoint, no user/model-influenced URL; sacred-path refusal empirically re-verified live by the reviewer (a maliciously-targeted `propose_patch` call is refused by `classifyDraftAction`, same as every other path).

**Non-blocking follow-up noted, not required for this commit:** `ToolCallLogEntry.args` stores raw model-submitted arguments verbatim (not output-bounded/secret-scanned) — fine while nothing persists/logs this outside-process; should get the same discipline as `IdeToolResult.output` before any caller starts logging it externally.
