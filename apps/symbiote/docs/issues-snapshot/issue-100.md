## What it is

A coordination primitive that turns pairwise Weave messaging into a **governed mesh**, using
**shared verifiable randomness (drand quicknet)** as the trust anchor. It gives a set of nodes a fair,
publicly-checkable way to (a) elect a leader, (b) draw a k-of-n review committee, and (c) make a
future-round sealed commit that cannot be opened before a chosen drand round.

Prototype: `scratchpad/mesh_heartbeat/` — `beacon.py`, `nodes.py`, `sortition.py`, `timelock.py`,
`adversary.py`, `run_heartbeat.py`, `outputs/mesh_heartbeat_findings.json`.

## What is REAL in the prototype (verified this run)

- **Live drand quicknet** rounds (chain `52db9ba7…`, period 3s, `bls-unchained-g1-rfc9380`); the
  `randomness == SHA256(signature)` check **passes** (`randomness_verified:true`).
- **Fair leader election** `leader = argmin_i SHA256(randomness‖domain_tag‖pubkey_i)` and **k-of-n
  review-sortition**, both **independently re-verified from public inputs**.
- **Ephemeral ed25519 identities** + a **non-malleable binding signature** over
  `(committer_pubkey, target_round, payload_commit)`.
- **Future-round unlock + real late open**: after the target drand round actually emitted, the seal
  opened (`opened:true, integrity_ok:true`), plaintext recovered, unlock-round randomness re-verified
  real.

## Adversarial results (measured)

| attack | result |
|---|---|
| bias the external beacon from a mesh node | **IMPOSSIBLE** (randomness is the external threshold-BLS network's; mesh contributes no input) |
| grind own pubkey after randomness | **succeeds IFF roster not frozen** → operational rule |
| round-shopping | **succeeds IFF round not pinned** → operational rule |
| open early via honest verifier | **BLOCKED** (round gate) |
| open early bypassing verifier | **succeeds-in-sim ONLY** (simulation gap, see B1 below) |
| tamper round/payload reusing sig | **BLOCKED** (ed25519 non-malleable) |

## Blockers before ANY landing (honest, load-bearing)

- **B1 — SIMULATED tlock (the crypto hole).** drand tlock IBE-encryption-to-a-round is **not**
  implemented (no BLS12-381 pairing lib in sandbox). It is modeled as a verifier-enforced round gate
  over an XOR seal **with the seal key held in-process**, so an attacker who bypasses the verifier and
  holds that key **CAN open early in the sim** (adversary check B2). This is a property of the
  **simulation, not of real tlock**, where the plaintext is cryptographically unrecoverable until the
  network emits the round. **Fix: use real drand `tlock` (`py_ecc.bls` / drand `timelock`).** Until
  then, do not rely on the sealed-commit for secrecy.
- **B2 — BLS sig not verified vs chain pubkey.** We confirm `randomness==SHA256(sig)` but do not
  verify the BLS signature against the chain public key (same missing pairing lib). Full trustlessness
  needs it.
- **B3 — two operational rules are mandatory, not optional:**
  1. **Freeze the mesh roster (pubkeys) BEFORE the beacon round** (blocks the grind-pubkey attack).
  2. **Pin the round deterministically to the heartbeat epoch** — `round = round_at_time(epoch_start)`
     — so nobody hand-picks a favorable round (blocks round-shopping).

## Proposed roadmap (if owner approves the direction)

1. Swap the sim seal for real drand tlock; add BLS-vs-chain-pubkey verification → closes B1/B2.
2. Encode the two operational rules (frozen roster + pinned round) as enforced invariants with tests,
   not documentation → closes B3.
3. Only then consider a `lane:safety-rail` proposal to wire the primitive to a real (still
   advisory-only) mesh, behind the governed loop.

Proven twice on the LIVE chain: encrypt a sealed commit to a round ~35–45s ahead → **before** the round the target signature does not exist (HTTP 425 Too Early) and decryption with any wrong-round sig is rejected → **early decrypt is cryptographically impossible**; **after** the round publishes, its sig BLS-verifies against the pinned pubkey and decryption returns the exact payload (SHA256 match).
